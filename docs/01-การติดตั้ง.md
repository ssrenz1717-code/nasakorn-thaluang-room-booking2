# คู่มือติดตั้ง — ระบบจองห้องประชุม

ทำตามลำดับนี้ ข้ามข้อไม่ได้ ใช้เวลาประมาณ 20-30 นาทีสำหรับครั้งแรก

ทุกอย่างในคู่มือนี้ **ฟรี ไม่ต้องผูกบัตรเครดิต**

---

## ขั้นที่ 1 — สร้างโปรเจกต์ Apps Script

1. เปิด https://script.google.com แล้วกด **โปรเจกต์ใหม่**
2. เปลี่ยนชื่อโปรเจกต์เป็น `ระบบจองห้องประชุม`
3. จดรหัสโปรเจกต์ไว้: เมนู **Project Settings** (ไอคอนเฟือง) → คัดลอก **Script ID**

### วิธีอัปโหลดโค้ด — เลือกทางใดทางหนึ่ง

**ทาง ก (แนะนำ) ใช้ clasp อัปโหลดจากเครื่อง**

```bash
npm install -g @google/clasp
clasp login

cd apps-script
# สร้างไฟล์ .clasp.json โดยใส่ Script ID ที่คัดลอกมา
cat > .clasp.json <<JSON
{
  "scriptId": "วาง_SCRIPT_ID_ที่นี่",
  "rootDir": "."
}
JSON

cd .. && npm run build:domain   # สร้าง apps-script/Domain.gs ให้เป็นเวอร์ชันล่าสุดก่อนทุกครั้ง
cd apps-script && clasp push
```

**ทาง ข อัปโหลดด้วยมือ** — สร้างไฟล์ใน Apps Script Editor ทีละไฟล์แล้วคัดลอกเนื้อหาจาก
โฟลเดอร์ `apps-script/` ไปวาง (ชื่อไฟล์ต้องตรงกัน ไม่ต้องใส่นามสกุล `.gs`)

> ⚠️ **ทุกครั้งที่แก้โค้ดใน `shared/` ต้องรัน `npm run build:domain` ก่อน push**
> ไม่งั้น Apps Script จะยังใช้ domain logic เวอร์ชันเก่า

## ขั้นที่ 2 — ไม่ต้องตั้งค่า Script Properties เอง

หน้าเข้าสู่ระบบเลือกได้ 2 ทาง: **ชื่อผู้ใช้ + รหัสผ่าน** หรือ **PIN 6 หลักอย่างเดียว** (ผู้ลงนามใส่ PIN อีกครั้งทุกครั้งที่กดอนุมัติ แทนลายเซ็น)
ไม่ใช้บัญชี Google จึงไม่ต้องสร้าง OAuth Client ID
ค่าที่ระบบต้องใช้ (`SPREADSHEET_ID`, `SESSION_SECRET`, `PIN_PEPPER`) สคริปต์ติดตั้งในขั้นถัดไปสร้างให้เองทั้งหมด

> `PIN_PEPPER` คือกุญแจลับที่ผสมตอนเก็บรหัสผ่านและ PIN — **ห้ามลบหรือแก้** ไม่งั้นรหัสของทุกคนจะใช้ไม่ได้
> (ถ้าเผลอลบ ให้รัน `setupSystem()` ใหม่ แล้วผู้ดูแลรีเซ็ตรหัสผ่านและ PIN ให้ทุกคน)

## ขั้นที่ 4 — รันสคริปต์ติดตั้ง

1. ใน Editor เลือกไฟล์ `90_Setup`
2. เลือกฟังก์ชัน `setupSystem` จากเมนูด้านบน แล้วกด **Run**
3. ครั้งแรก Google จะขอสิทธิ์ → **Review permissions** → เลือกบัญชีของคุณ →
   หน้าจอจะเตือนว่า "Google hasn't verified this app" → **Advanced** → **Go to ... (unsafe)** → **Allow**
   (เตือนเพราะเป็นสคริปต์ที่คุณเขียนเอง ยังไม่ผ่านการตรวจของ Google — ปกติ)
4. อ่านผลใน **Execution log** ควรเห็น:
   - ลิงก์ไฟล์ข้อมูลที่สร้างใหม่
   - สร้างชีตครบ 8 ชีต (Users, Rooms, Bookings, Notifications, AuditLogs, Settings, Meta, Announcements)
   - เพิ่มห้องประชุม 7 รายการ (6 ห้องของวิทยาลัย + "อื่น ๆ (ระบุสถานที่)") — **แก้ความจุจริงในชีต Rooms** เพราะตัวเลขเริ่มต้นเป็นค่าประมาณ
   - เขียนค่าตั้งค่าเริ่มต้น 12 รายการ
   - **สร้างบัญชีตั้งต้น 4 บัญชี พร้อมรหัสผ่านและ PIN แรกเข้า** — จดจาก log ไว้ (แสดงครั้งเดียว ระบบไม่เก็บค่าจริง)

     | ชื่อผู้ใช้ | ชื่อ | สิทธิ์ |
     |---|---|---|
     | `shoyu` | shoyu | ผู้ดูแลระบบ |
     | `watcharapong` | นายวัชรพงศ์ โสภา | ลงนามขั้นที่ 1 ตรวจสอบห้อง |
     | `ekkarat` | นายเอกราช เขียวทอง | ลงนามขั้นที่ 2 รับรอง |
     | `chatree` | นายชาตรี เริงชัยภูมิ | ลงนามขั้นที่ 3 อนุมัติ |

     ทำหายก็ไม่เป็นไร: เข้าสู่ระบบด้วย `shoyu` แล้วกด **รีเซ็ตรหัสผ่าน** หรือ **รีเซ็ต PIN** ในหน้าจัดการผู้ใช้

> ระบบอนุมัติเปิดเป็นค่าเริ่มต้นสำหรับการติดตั้งใหม่ เพื่อให้ผู้ดูแลพิจารณาคำขอก่อนใช้ห้อง
> ถ้าเป็นไฟล์ชีตเดิม ให้ตรวจชีต `Settings` ว่าค่า `approvalRequired` เป็น `TRUE`
> และรัน `migrateSheets()` หลังอัปโหลดโค้ดรุ่นใหม่เพื่อเพิ่มคอลัมน์คำขอและข้อมูลอุปกรณ์

### เพิ่มผู้ใช้ กำหนดสิทธิ์อนุมัติ และห้องที่จองได้

ทำในหน้าเว็บ เมนู **จัดการผู้ใช้** (เห็นเฉพาะผู้ดูแลระบบ) ไม่ต้องแก้ชีตเอง:

- **เพิ่มผู้ใช้** — ตั้งชื่อผู้ใช้ ชื่อ-นามสกุล รหัสผ่าน และ PIN แรกเข้า (ระบบสุ่มให้ได้) จะขึ้นค้างบนจอจนกดรับทราบ
- **สิทธิ์การใช้งาน** — ผู้ใช้งาน / ลงนามขั้นที่ 1–3 / ผู้ดูแลระบบ เปลี่ยนแล้วมีผลตั้งแต่การกดครั้งถัดไป
  คำขอทุกรายการต้องผ่าน 3 ขั้นตามลำดับ แต่ละขั้นต้องเป็นคนละบัญชี
- **ห้องที่จองได้** — ทุกห้อง หรือเลือกเฉพาะบางห้อง (ผู้ใช้จะเห็นและจองได้เฉพาะห้องนั้น เซิร์ฟเวอร์ตรวจซ้ำตอนจอง)
- **รีเซ็ตรหัสผ่าน / รีเซ็ต PIN** (แยกกัน) — ค่าเดิมใช้ไม่ได้ทันที และทุกเครื่องที่เข้าระบบด้วยบัญชีนั้นจะถูกออกจากระบบ
- **ปิดการใช้งาน / ลบ** — ปิดแล้วประวัติยังอยู่ ลบแล้วเข้าระบบไม่ได้อีก รายการจองเก่ายังอยู่
- ระบบกันไว้ให้: ลบหรือลดสิทธิ์ตัวเองไม่ได้ และต้องเหลือผู้ดูแลที่ใช้งานได้อย่างน้อย 1 คนเสมอ

- **PIN ต้องไม่ซ้ำกับคนอื่น** เพราะใช้เข้าระบบได้โดยไม่ต้องใส่ชื่อ ระบบจะเตือนถ้าตั้งซ้ำ
- รหัสผ่านผิด 5 ครั้งติดกัน บัญชีนั้นจะถูกล็อก 15 นาที (หรือให้ผู้ดูแลรีเซ็ตเพื่อปลดล็อกทันที)
- ทาง PIN อย่างเดียวไม่รู้ว่าใครกำลังใส่ จึงนับ PIN ผิดรวมทั้งระบบ ครบ 30 ครั้งในชั่วโมงเดียว ปิดทาง PIN ไว้ถึงต้นชั่วโมงถัดไป (ทางรหัสผ่านยังเข้าได้ตามปกติ)

### 🔒 สำคัญที่สุดในคู่มือนี้

ไฟล์ข้อมูลที่สร้างขึ้น **ต้องไม่แชร์ให้พนักงานเด็ดขาด** ไม่ว่าจะแบบดูอย่างเดียวหรือแก้ได้

เพราะถ้าพนักงานเปิดไฟล์ได้ เขาจะ:
- แก้สถานะการจองของตัวเองเป็น "ยืนยันแล้ว" ได้เอง
- เปลี่ยน `role` ของตัวเองเป็น `admin` ได้
- ลบการจองของคนอื่นได้ โดยไม่มีร่องรอยใน AuditLogs

ระบบสิทธิ์ทั้งหมดอยู่ในโค้ด Apps Script — การแชร์ไฟล์คือการเปิดประตูหลังข้ามทุกอย่าง
พนักงานต้องเข้าทางหน้าเว็บทางเดียว

ต้องขึ้น `[ผ่าน]` ทุกข้อ เช่น:

```
[ผ่าน]   โค้ด domain ถูกโหลดเข้ามาแล้ว
[ผ่าน]   ตรรกะเวลาทับซ้อนทำงานถูกต้อง
[ผ่าน]   เวลาไทยถูกต้อง (ไม่เลื่อนวัน)
[ผ่าน]   ค่าคอนฟิกครบ
[ผ่าน]   เปิดไฟล์ข้อมูลได้
[ผ่าน]   ชีตและคอลัมน์ครบทุกชีต
[ผ่าน]   อ่านค่าตั้งค่าระบบได้
[ผ่าน]   จับล็อกและปล่อยล็อกได้ (กลไกกันจองซ้ำ)
[ผ่าน]   ออกและตรวจ session token ได้ด้วยกุญแจจริง
[ผ่าน]   มีผู้ดูแลระบบที่ใช้งานได้
[ผ่าน]   hash PIN ตรวจกลับได้และแยก salt จริง
[ผ่าน]   ตัวนับเวอร์ชันข้อมูลอ่านได้
```

ถ้ามีข้อไม่ผ่าน ข้อความจะบอกตรง ๆ ว่าต้องไปแก้อะไร

## ขั้นที่ 6 — Deploy เป็น Web App

1. กด **Deploy → New deployment** (ไอคอนเฟืองข้าง ๆ เลือก **Web app**)
2. ตั้งค่า:
   - Description: `v1`
   - **Execute as: Me** ← สำคัญ สคริปต์ต้องรันด้วยสิทธิ์ของคุณจึงจะเปิดไฟล์ข้อมูลได้
   - **Who has access: Anyone** ← จำเป็น เพราะพนักงานใช้ Gmail ส่วนตัวนอกโดเมน
3. กด **Deploy** แล้วคัดลอก **Web app URL** (ลงท้ายด้วย `/exec`)

> "Who has access: Anyone" **ไม่ได้แปลว่าใครก็เข้าถึงข้อมูลได้**
> ทุกคำสั่งที่แตะข้อมูลต้องมี session token ที่ถูกเซ็นด้วยกุญแจลับของระบบ และบัญชีนั้น
> ต้องอยู่ในชีต Users และเปิดใช้งานอยู่ด้วย คนที่ยิง URL ตรง ๆ จะได้แค่
> `{"ok":false,"error":{"code":"UNAUTHENTICATED"}}`

### ทดสอบว่า deploy สำเร็จ

```bash
curl -L "วาง_WEB_APP_URL_ที่นี่"
# ควรได้: {"ok":true,"data":{"service":"ระบบจองห้องประชุม","serverTime":"..."}}
```

ถ้าต้องใส่ `-L` เพราะ Apps Script ตอบ 302 ไปที่ `script.googleusercontent.com` ก่อน — เป็นเรื่องปกติ

## ขั้นที่ 7 — ทุกครั้งที่อัปเดตโค้ด

```bash
npm run verify        # typecheck + เทสทั้งหมดต้องผ่านก่อน
npm run build:domain  # สร้าง Domain.gs ใหม่
cd apps-script && clasp push
```

จากนั้นใน Apps Script: **Deploy → Manage deployments → แก้ไข deployment เดิม → Version: New version → Deploy**

> ถ้าสร้าง deployment ใหม่แทนการแก้ของเดิม URL จะเปลี่ยน และหน้าเว็บจะคุยกับ server ไม่ได้

|---|---|---|
| `ยังไม่ได้ตั้งค่า SPREADSHEET_ID` | ยังไม่รัน setupSystem | รัน `setupSystem()` |
| `ยังไม่ได้ตั้งค่า PIN_PEPPER` | ยังไม่รัน setupSystem หลังอัปเดตโค้ด | รัน `setupSystem()` |
| `ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง` | พิมพ์ผิด หรือยังไม่มีบัญชี | ให้ผู้ดูแลตรวจชื่อผู้ใช้ หรือรีเซ็ตรหัสผ่าน |
| `PIN ไม่ถูกต้อง` | PIN ผิด (ตอนเข้าระบบหรือตอนลงนาม) | ลองใหม่ หรือให้ผู้ดูแลรีเซ็ต PIN |
| `ปิดการเข้าด้วย PIN ชั่วคราว` | PIN ผิดรวมทั้งระบบครบ 30 ครั้งในชั่วโมงนี้ | เข้าด้วยชื่อผู้ใช้และรหัสผ่านแทน หรือรอชั่วโมงถัดไป |
| `PIN นี้มีคนใช้แล้ว` | ตั้ง PIN ซ้ำกับบัญชีอื่น | กดสุ่มใหม่ |
| `ใส่รหัสผิดหลายครั้ง บัญชีนี้ถูกล็อกชั่วคราว` | ผิด 5 ครั้งติดกัน | รอ 15 นาที หรือให้ผู้ดูแลรีเซ็ต |
| ลืมรหัสของ `shoyu` และไม่มีผู้ดูแลคนอื่น | — | ลบแถว `shoyu` ในชีต Users แล้วรัน `setupSystem()` จะสร้างใหม่พร้อมรหัสผ่านและ PIN ใหม่ใน log |
| `ไม่พบชีต "..."` | สร้างฟิลด์ใหม่ในโค้ดแล้วแต่ยังไม่ migrate | รัน `migrateSheets()` (ไม่ลบข้อมูลเดิม) |
| `ระบบกำลังประมวลผลคำขอจำนวนมาก` | มีคนจองพร้อมกันมาก คิวล็อกเกิน 20 วินาที | ปกติในชั่วโมงเร่งด่วน กดอีกครั้ง — นี่คือกลไกที่ป้องกันการจองซ้ำกำลังทำงาน |
| หน้าเว็บขึ้น CORS error | ส่ง `Content-Type: application/json` | ต้องส่งเป็น `text/plain` เพื่อให้เบราว์เซอร์ไม่ยิง preflight (โค้ดฝั่งหน้าเว็บจัดการให้แล้ว) |
